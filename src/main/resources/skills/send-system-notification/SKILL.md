# 发送系统通知邮件

## 概述

通过青语（项目名称）向系统注册用户发送官方系统通知邮件，用于系统上线、功能发布、系统维护、系统公告等场景。
发件邮箱固定使用项目配置文件（spring.mail.username）中的邮箱，发件人名称固定为「聴夏」。
通知正文基于项目 templates 目录下的系统通知邮件 HTML 模版（system-notification.html）渲染，模版内固定包含项目名称「青语」与发送人「聴夏」。

## 适用场景

- 系统上线通知：新系统/新站点上线，告知用户可开始使用；
- 功能发布通知：新功能上线或重大更新，说明新能力与使用方式；
- 系统维护通知：停机维护、升级、迁移等，说明维护时间与影响范围；
- 系统公告：面向全体用户的重要公告事项。

## 强制规则

1. 收件人校验（发送前必须完成，以下三条路径均强制）：
   - 用户提供姓名/昵称：必须先调用 verifyRecipient 工具按用户名/昵称查询系统用户表，
     确认该用户存在且状态正常（未删除、未封禁、未禁用），并获得其注册邮箱；查无此人时禁止发送并明确告知用户。
   - 用户直接提供邮箱：必须先调用 verifyRecipient 工具校验该邮箱在系统用户表中已注册；
     未注册时禁止发送并明确告知用户。
   - 用户要求向所有人/全体用户发送（如"给所有用户发系统维护通知"）：必须先调用 getAllUserEmails 工具
     获取系统中所有状态正常用户的邮箱列表，严禁自行猜测或拼凑邮箱。
2. 禁止猜测或编造收件邮箱：任何情况下都不得使用未经 verifyRecipient / getAllUserEmails 校验通过的邮箱发送邮件。
3. 系统内部邮箱禁止发送：以 @qy.com 结尾的邮箱为系统内部邮箱，getAllUserEmails 返回的列表中已自动过滤此类邮箱；
   任何情况下都严禁将 @qy.com 结尾的邮箱作为收件人，sendSystemNotification 工具会一律拒绝此类邮箱。
4. 群发隐私保护（多人加密发送）：收件人多于 1 人时，工具内部会自动使用密送（Bcc）方式发送，
   所有接收人互不可见对方的邮箱地址；收件人只有 1 人时使用普通发送（To）。此项由工具自动处理，模型无需干预。
5. 邮件主题：由大模型结合通知类型与用户输入生成，简洁明确（如"青语系统维护通知（10月12日 22:00-24:00）"），
   不超过 50 个字；不得使用固定主题字符串，工具内部对超长主题会自动截断。
6. 邮件正文内容：由大模型根据用户输入生成，要求正式、清晰、完整，必须包含通知的关键信息
   （如时间、影响范围、操作建议、联系方式等），可分段表述；
   严禁编造用户未提供的关键信息（如用户未说明维护时间，不得自行编造时间，必须先向用户确认）。
7. 邮件正文必须使用项目 templates 目录下的系统通知邮件 HTML 模版（system-notification.html）。
   模版内已包含项目名称「青语」与发送人「聴夏」，不得自行构造邮件内容替代模版。
8. 发送动作必须通过调用 sendSystemNotification 工具完成；只有工具返回"发送成功"后，才可告知用户"邮件已发送"，
   严禁未调用工具就声称已发送，严禁编造发送结果。
9. 发件邮箱与发件人名称由系统固定配置（spring.mail.username / 聴夏），任何情况下不得更改。
10. 通知类型（notificationType 参数）从以下四类中选取：系统上线、功能发布、系统维护、系统公告；
    用户意图无法归入四类时使用"系统通知"。

## 标准流程

1. 判断通知类型：结合用户输入归入"系统上线 / 功能发布 / 系统维护 / 系统公告"之一。
2. 解析收件人：区分"按姓名/昵称"、"按邮箱"还是"向所有人发送"。
3. 收件人校验：按姓名/昵称或按邮箱 → 调用 verifyRecipient；向所有人发送 → 调用 getAllUserEmails 获取全部注册邮箱。
   校验通过则进入下一步；失败则终止流程并如实告知用户校验结果。
4. 核对通知关键信息：通知必须包含的关键信息（如维护/上线时间、影响范围）用户未提供时，先向用户追问确认，严禁编造。
5. 结合通知类型与用户输入生成邮件主题（不超过 50 个字）与正式的通知正文内容（可分段）。
6. 调用 sendSystemNotification 发送邮件（多收件人时工具自动以 Bcc 密送，保护邮箱隐私）。
7. 根据工具返回结果向用户汇报（发送成功或失败原因）。
