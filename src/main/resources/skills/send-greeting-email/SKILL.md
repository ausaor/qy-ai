# 向系统用户发送问候邮件

## 概述

通过青语（项目名称）向系统注册用户发送一封温馨的问候邮件。
发件邮箱固定使用项目配置文件（spring.mail.username）中的邮箱，发件人名称固定为「聴夏」。

## 强制规则

1. 收件人校验（发送前必须完成，以下三条路径均强制）：
   - 用户提供姓名/昵称（如"向 Spring 发送问候"）：必须先调用 verifyRecipient 工具按用户名/昵称查询系统用户表，
     确认该用户存在且状态正常（未删除、未封禁、未禁用），并获得其注册邮箱；查无此人时禁止发送并明确告知用户。
   - 用户直接提供邮箱：必须先调用 verifyRecipient 工具校验该邮箱在系统用户表中已注册；
     未注册时禁止发送并明确告知用户。
   - 用户要求向所有人/全体用户发送（如"给所有人发一封问候邮件"）：必须先调用 getAllUserEmails 工具
     获取系统中所有状态正常用户的邮箱列表，严禁自行猜测或拼凑邮箱。
2. 禁止猜测或编造收件邮箱：任何情况下都不得使用未经 verifyRecipient / getAllUserEmails 校验通过的邮箱发送邮件。
3. 系统内部邮箱禁止发送：以 @qy.com 结尾的邮箱为系统内部邮箱，getAllUserEmails 返回的列表中已自动过滤此类邮箱；
   任何情况下都严禁将 @qy.com 结尾的邮箱作为收件人，sendGreetingEmail 工具会一律拒绝此类邮箱。
4. 群发隐私保护：收件人多于 1 人时，工具内部会自动使用密送（Bcc）方式发送，所有接收人互不可见对方的邮箱地址；
   收件人只有 1 人时使用普通发送（To）。此项由工具自动处理，模型无需干预。
5. 邮件主题：由大模型结合问候场景（节日、场合、用户意图等）生成，简洁得体，不超过 20 个字；
   不得使用固定主题字符串，工具内部对超长主题会自动截断。
6. 邮件正文必须使用项目 templates 目录下的问候邮件 HTML 模版（greeting-email.html）。
   模版内已包含项目名称「青语」与发送人「聴夏」，不得自行构造邮件内容替代模版。
7. 发送动作必须通过调用 sendGreetingEmail 工具完成；只有工具返回"发送成功"后，才可告知用户"邮件已发送"，
   严禁未调用工具就声称已发送，严禁编造发送结果。
8. 发件邮箱与发件人名称由系统固定配置（spring.mail.username / 聴夏），任何情况下不得更改。
9. 问候语内容要求（greeting 参数）：简洁、温馨、正向，一两句话即可；可结合用户意图或节日/场景生成，
   禁止包含广告、营销链接或不雅内容。问候语仅为正文内容，不要再包含「亲爱的…」等称呼敬语。
10. 开头敬语（salutation 参数）：由大模型单独生成，如「亲爱的朋友：」，放于正文之前，不超过 30 个字；
    未提供时工具自动使用默认称呼（单个收件人用昵称，如「亲爱的 + 昵称 + ：」）。

## 标准流程

1. 解析收件人：区分"按姓名/昵称"、"按邮箱"还是"向所有人发送"。
2. 收件人校验：按姓名/昵称或按邮箱 → 调用 verifyRecipient；向所有人发送 → 调用 getAllUserEmails 获取全部注册邮箱。
   校验通过则进入下一步；失败则终止流程并如实告知用户校验结果。
3. 结合场景生成邮件主题（不超过 20 个字）、开头敬语（如「亲爱的朋友：」）与问候正文（简洁温馨，正文不包含敬语）。
4. 调用 sendGreetingEmail 发送邮件（多收件人时工具自动以 Bcc 密送，保护邮箱隐私）。
5. 根据工具返回结果向用户汇报（发送成功或失败原因）。
